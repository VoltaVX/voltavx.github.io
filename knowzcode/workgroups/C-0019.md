## 5. Exact shared rules to apply

All dimensions below describe default-root CSS pixels; reuse existing rem/clamp tokens rather than introducing fixed root size.

| --- | --- | --- |

| Major section separation | 64–120px fluid, once | Following section margin; --section-space |
| Heading group to component group | 24–32px | --heading-gap; one owner only |
| Editorial tracks | 20–48px | Parent grid gap; --editorial-gap |

| Example to callout | 16px stacked; 26px wide | Existing pathway caption tokens |

Padding is for a container's internal inset. Gap is for direct flex/grid siblings, with child block margins reset. Leading margin is for normal-flow text/section separation. Padding and margin may coexist only when they represent different relationships. Record the effective visible distance, not merely one declaration. Preserve documented pathway/local exceptions and bottom-aligned auto margins.

Typography: system sans; primary headings #171922, supporting paragraphs/lists/metadata #585D70, accent #5147D9. Headings 700 with -.035em tracking. Display 36–72px, major section 36–54px, secondary 36–45px, cards 22–26px, body 16–18px, card body16px, captions14px, eyebrows12px, actions15px. Use existing leading tokens. One H1 per page; semantic heading level does not automatically imply display size. Paper titles and Resume entry H2s use card size. Prose measure 56–65ch. Short approved serif italic emphasis remains; no long italic paragraphs.

Materials: navigation/filter uses --glass-* (60% white,24px blur,130% saturation). Standalone content uses --content-* (70% white,18px blur,120% saturation, bright rim/inset highlight/quiet shadow). Feature shells use --feature-background. Nested diagram cells, source panels and native fields stay opaque without another blur. Text remains fully opaque. Preserve glass-off, reduced-transparency, contrast, forced-color, unsupported-browser and print fallbacks. Reuse 24px card,32px feature and16px example corners. Check actual backdrop visibility; a blur declaration under an opaque fill is not sufficient.

## 8A. Concrete style-merging techniques

The merge must exploit the current styling system rather than build a parallel theme. Use the least invasive option below, in order.

1. **Reuse the actual component.** StudyDiagram already serves homepage and detail variants; retain that shared rendering path. Use ActionLink and SectionHeading where their props/slots express the required content. Preserve their interfaces rather than hardcoding lookalikes.
2. **Share the existing style rule when markup cannot yet be shared.** The detail routes contain stored HTML. Group equivalent existing homepage/detail selectors under the same layered rule where anatomy is genuinely equivalent, or apply the established public class to the migrated markup. Keep the `.detail-page` boundary for layout-specific differences. Do not paste the homepage declaration block into seventeen selectors.
3. **Separate composition from appearance.** A route variant may own grid columns, order, alignment and media placement. It must inherit font, text colors, border radius, control sizing, padding and material from existing roles. For instance, a research feature can use a copy/diagram grid while its card title and surface remain identical to other cards.
4. **Use existing custom properties as the join.** Route-level rules consume `--editorial-gap`, `--card-padding`, `--panel-padding`, `--section-space`, `--text-h3`, `--color-muted`, `--content-bg` and `--content-filter`. Resolve the final cascade, including later fluid token declarations, rather than copying earlier fallback values. New tokens are justified only by a reusable semantic role absent from the current system; document them before use.
5. **Use small documented variants for real differences.** A feature panel uses panel padding; an ordinary card uses card padding. A native diagram nested inside a frosted card uses an opaque inset. Express this through the existing role/variant where possible, not an arbitrary route override. Avoid one generic card wrapper around every section.
6. **Preserve the five-layer cascade.** Keep tokens/base/layout/components/utilities and current import order. Use low-specificity grouping such as existing `:where()` patterns where appropriate. Inspect scoped/unlayered styles before adding a rule. Remove obsolete rules within touched scope; never fix a conflict with `!important` or a longer selector chain.
7. **Share geometry without flattening meaning.** Project cards, evidence cards and Resume entries can share inset/rim/type roles while retaining different semantic HTML and content order. A five-step pathway and six-step process list must remain separate structures, even when they share number-tile styling.

Before changing each family, write a short mapping: source selector/anatomy → current component or style role → permitted composition delta → affected contract → acceptance check. Verify computed values against the homepage counterpart at the same viewport. Distinguish intentional role differences from accidental drift. Re-run the counterpart's homepage regression check whenever its shared rule changes.

No wholesale legacy CSS import, second token palette, duplicated breakpoint system, page-specific type scale, new styling framework, or speculative renderer abstraction is part of this plan. The best merge is often to leave existing shared appearance untouched and change only the source layout relationship that differs.
