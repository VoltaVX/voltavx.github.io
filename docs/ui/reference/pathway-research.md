# Pathway design research and revision

Date: 17 October 2026. Portfolio: Juan Lopez / VoltaVX.

## Recommendation

Keep the five original cards and their alternating order. Replace full website screenshots with focused interface crops. Use one quiet vertical sequence rail, short local callouts, and one visible focal highlight. Keep additional research notes behind one optional source/details link.

The previous version made ten large surfaces compete: five explanation cards and five complete website previews. Repeated navigation, multiple caption levels, long connectors, and strongly tilted planes added more reading paths. The solution is to reduce the simultaneous visual load while preserving the original content.

## Review method and evidence limits

I opened first-party pages from 23 distinct websites. Four representative rendered-page checks covered Mike De Bastiani, Emil Kowalski, Rauno Freiberg, and Paco Coursey's craft index. Other entries were reviewed through retrieved page structure, author descriptions, code/example structure, and image descriptions. I did not test every live animation or measure every site's spacing. Exact CSS values below are portfolio recommendations, not measurements copied from these sites.

The sample includes process-to-evidence portfolios, developer explainers, and adjacent product walkthroughs. It does not claim that all 23 sites use a literal pathway diagram. The closest direct references are Mike's Workflow Atlas, Paco's timeline, Jimmy Weber's development timeline, and Spline's named workflow. The other sites supply relevant lessons about component demonstration, reading order, and density.

AniDesignIt's detail page and Devouring Details did not return usable detail in this retrieval. They are excluded from the count. Sites and pages can change. This is a design review, not a user experiment or a ranking of site quality.

## Strongest transferable patterns

### 1. Separate overview from depth

Mike's case study explicitly separates fast scanning from deeper exploration and uses expandable detail. Lee's optional longer bio provides a simpler example of choosing depth. Keep all original card text, as requested. Move the added research subpoints out of the default pathway view. This removes duplicated explanation without changing the original cards.

### 2. Show the component that proves the point

Emil's component case study and Clerk's component presentation are strong references. A button example can explain salience. A selected tab can explain cues. A stepper can explain progress. These examples do not need a full website header, portrait, and unrelated content. Use a crop that remains recognizable as part of the portfolio's design system.

### 3. Use one sequence axis

Paco's timeline uses a shared axis. Spline names its workflow stages directly. For this portfolio, use a quiet straight rail and five ordered nodes. Each local callout branches from that system. Remove the independent winding vine.

### 4. Control the amount of emphasis

Josh's and Maxime's articles introduce concepts through successive examples. The inference for this page is to limit each stage to one principal target. This is a design inference; those sites do not prescribe this portfolio's exact layout. Use indigo for the active target. Keep other rules, card edges, and stage markers quiet.

### 5. Make motion explain a change

Emil's essay on animation explains the importance of purpose and frequency. DataMorph describes motion as information. Preserve the mirrored perspective in a much smaller range. Animate the target emphasis only when it helps orientation. Do not rotate the cards, spin the screens, or move body copy.

### 6. Repeat geometry, not chrome

Linear, Vercel, Framer, Stripe, Resend, and Raycast organize different capabilities into repeated sections. For this portfolio, repeat the same card width, crop size, and row rhythm. Do not repeat an entire site's navigation within each embedded example.

## Revision decisions

| Previous design | Revised rule | Main reference |
| --- | --- | --- |
| Five full-page previews | Five component-level crops; no embedded global header | Emil; Clerk; Resend |
| Strong perspective on large planes | Mirrored Y rotation of at most 4 degrees and Z rotation of at most 1 degree | Retained user preference, bounded by the simpler composition |
| Winding path plus five leaders | One straight rail with short local branches | Paco; Spline |
| Five captions plus fifteen subpoint labels | One short annotation per crop; research notes at one source/details link | Mike; Lee |
| Multiple bright points in each row | One target per stage, one active focal highlight in a viewport | Josh; Maxime; Linear |
| Large overlaps and shadows | No content overlap; minimal borders and shadows | Readability requirement and portfolio tokens |
| Full application snapshots to show simple feedback | A small confirmation component | Emil; Clerk |
| Layout changes per example | Fixed card and crop columns with alternating placement | Brittany; repeated product section structure |

## Concrete revised geometry

At the 1,440 px reference viewport, retain the 1,200 px container and 120 px exterior margins. The original main cards stay 552 px wide, with 32 px padding and the original icon-left/text-right layout. Use a supporting crop no wider than 432 px and normally 160-240 px high.

For odd stages, place the card at container x=0 and the crop at x=672. For even stages, place the crop at x=96 and the card at x=648. This leaves a 120 px separation between the nearest card and crop edges. Keep a quiet rail at x=600. Keep the relevant target close to the crop edge facing its card, so the branch can remain approximately 120-180 px long.

Use at least 400 px per stage and 64 px between stages. Allow each card to grow for its original text. Give the intro 48 px before the first stage. Keep at least 96 px after the section. Apply spacing once at each boundary.

## Apple alignment

Apple's Materials guidance distinguishes functional glass from ordinary content. Keep glass in the functional layer. The pathway cards and supporting crops are content surfaces. Use the existing ivory, indigo, type, radius, and spacing tokens. The current project rules remain the authority for custom dimensions.

Official base: [Materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Layout](https://developer.apple.com/design/human-interface-guidelines/layout), [Motion](https://developer.apple.com/design/human-interface-guidelines/motion).

## Acceptance checks

1. All five original card texts remain intact.
2. The icon-left arrangement and upper-left numbered badge remain intact.
3. No embedded full-site header, browser frame, or repeated portrait is visible.
4. Each stage has one small example, one target, and at most one short annotation.
5. The rail and local branch form one sequence system. There is no independent winding path.
6. No panel overlaps text or another panel.
7. Mirrored perspective is subtle. Text is never mirrored.
8. The scene remains clear with motion off and with opaque surfaces.
9. The research report lists all 23 primary sites with the type of evidence used.
10. Exact implementation dimensions come from design.md. Raster images remain concepts.
